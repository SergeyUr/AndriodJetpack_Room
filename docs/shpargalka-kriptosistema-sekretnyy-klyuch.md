# Шпаргалка: криптосистема с секретным ключом

> Тема: модель симметричной криптосистемы · абсолютно стойкий шифр · блочные и поточные шифры · свойства гаммирования

---

## 1. Модель криптосистемы с секретным ключом

**Симметричная (с секретным ключом)** — один ключ \(K\) у отправителя и получателя.

| Компонент | Обозначение |
|---|---|
| Открытые тексты | \(M\) |
| Шифртексты | \(C\) |
| Ключи | \(K\) |
| Шифрование | \(E_K: M \to C\) |
| Расшифрование | \(D_K: C \to M\) |

**Корректность:** \(D_K(E_K(m)) = m\)

**Принцип Керкгоффса:** стойкость опирается на секретность ключа, а не алгоритма.

**Модели атак (по силе):**
- COA — только шифртекст
- KPA — известные пары \((m, c)\)
- CPA — выбранный открытый текст
- CCA — выбранный шифртекст

---

## 2. Абсолютно стойкий шифр (Шеннон)

**Совершенная стойкость:** шифртекст не даёт информации об открытом тексте.

\[
P(M=m \mid C=c) = P(M=m)
\]

То есть \(M\) и \(C\) статистически независимы.

### Необходимое условие
\[
|K| \ge |M|
\]
(ключ не короче сообщения / его энтропии)

### Одноразовый блокнот (OTP, Вернам)
\[
c_i = m_i \oplus k_i,\quad m_i = c_i \oplus k_i
\]

**Условия абсолютной стойкости OTP:**
1. ключ истинно случайный;
2. ключ равновероятный;
3. длина ключа = длина сообщения;
4. ключ используется **один раз**.

**Минусы:** генерация, доставка и хранение длинных ключей; повтор ключа убивает стойкость.

> На практике почти все шифры дают **вычислительную**, а не абсолютную стойкость.

## 3. Блочные и поточные шифры

### Блочные
Шифруют блоки фиксированной длины \(n\) (часто 64/128 бит):
\[
E_K: \{0,1\}^n \to \{0,1\}^n
\]

**Примеры:** AES, DES, ГОСТ 28147-89 («Магма»), «Кузнечик».

**Режимы работы:**
| Режим | Суть | Заметка |
|---|---|---|
| ECB | блок независимо | небезопасно |
| CBC | \(c_i = E_K(m_i \oplus c_{i-1})\) | нужен IV |
| CTR | гамма = \(E_K(\mathrm{nonce}\|ctr)\) | потоковый режим |
| GCM | CTR + аутентификация | AEAD |

**Плюсы:** универсальны; база для MAC, AEAD, PRF.  
**Минусы:** нужны режимы и padding (кроме потоковых режимов).

### Поточные
Генерируют **гамму** \(g = g_1 g_2 \ldots\) и накладывают на поток:
\[
c_i = m_i \oplus g_i
\]

Гамма зависит от ключа и часто от IV/nonce.

**Примеры:** ChaCha20, Salsa20; устаревшие/слабые: RC4, A5/1.  
Блочный в CTR/OFB тоже работает как потоковый.

**Плюсы:** скорость, малая задержка, удобно для голоса/видео.  
**Минусы:** нужна синхронизация; повтор гаммы катастрофичен.

### Сравнение одной строкой
- **Блочный** — перестановка блоков + режим.
- **Поточный** — генератор гаммы + XOR (или иное смешивание).

---

## 4. Свойства гаммирования

**Гаммирование** — наложение гаммы на открытый текст (обычно XOR).

### Ключевые свойства

1. **Обратимность**  
   \(m = c \oplus g\) при известной гамме.

2. **Линейность / повтор гаммы**  
   \[
   c_1 \oplus c_2 = m_1 \oplus m_2
   \]
   Одна гамма на два текста → утечка XOR открытых текстов (crib-dragging).

3. **Требования к гамме**  
   непредсказуемость · большой период · **одноразовость** (уникальный IV/nonce).

4. **Связь с OTP**  
   случайная одноразовая гамма = абсолютная стойкость;  
   псевдослучайная гамма = вычислительная стойкость.

5. **Синхронизация**  
   отправитель и получатель должны быть на одной позиции гаммы.

6. **Нет диффузии по сообщению**  
   бит \(m\) влияет только на соответствующий бит \(c\).

7. **Нет целостности**  
   противник может целенаправленно менять биты \(c\) → предсказуемо меняется \(m\).  
   Нужны MAC / AEAD (например, ChaCha20-Poly1305, AES-GCM).

## 30 секунд на ответ

Симметричная система: один секретный ключ, \(D_K(E_K(m))=m\), стойкость в ключе (Керкгоффс).  
Абсолютная стойкость по Шеннону: \(P(M|C)=P(M)\), нужно \(|K|\ge|M|\); пример — OTP.  
Блочные шифруют блоки (AES + режимы); поточные генерируют гамму и XOR-ят поток.  
Гаммирование обратимо, но повтор гаммы даёт \(c_1\oplus c_2=m_1\oplus m_2\); целостность само по себе не обеспечивает.

## Уточняющие вопросы (быстрые ответы)

| Вопрос | Короткий ответ |
|---|---|
| Чем абсолютная стойкость отличается от практической? | Абсолютная — даже при бесконечных ресурсах; практическая — вычислительно трудно |
| Почему ECB плох? | Одинаковые блоки → одинаковый шифртекст, видна структура |
| Зачем IV/nonce в потоковом шифре? | Чтобы гамма не повторялась при одном ключе |
| OTP при повторном ключе стоек? | Нет |
| Гаммирование защищает от подмены? | Нет, нужна аутентификация |
| CTR — блочный или потоковый? | Режим блочного, даёт потоковое шифрование |

## Мини-формулы

```
Шифрование:     c = E_K(m)
Расшифрование:  m = D_K(c)
Гаммирование:   c = m ⊕ g
Повтор гаммы:   c1 ⊕ c2 = m1 ⊕ m2
OTP:            |k| = |m|, k случайный, один раз
Шеннон:         P(M|C) = P(M)
```
